1. Big Data

2. V's of Big Data
   1. Volume : The amount of data generated and collected
   2. Velocity : The speed at which data is generated and processed
   3. Variety : The different types and forms of data
   4. Veracity : The accuracy and trustworthiness of the data
   5. Value : The usefulness and benefit derived from the data

3. Types of Big Data
   1. Structured Data : Data that is organized and can be easily stored in databases (e.g., SQL databases)
   2. Unstructured Data : Data that does not have a predefined structure (e.g., text, images, videos)
   3. Semi-Structured Data : Data that has some organizational structure but does not fit into traditional databases (e.g., JSON, XML)
4. Sources of Big Data
   1. Social Media : Platforms like Facebook, Twitter, and Instagram generate vast amounts of user-generated content
   2. IoT Devices : Sensors and devices connected to the Internet generate continuous streams of data
   3. E-commerce : Online shopping platforms collect data on user behavior, transactions, and preferences
   4. Healthcare : Medical records, patient data, and research data contribute to big data in healthcare
   5. Financial Services : Banks and financial institutions generate data from transactions, market trends, and customer interactions
5. Horizontal scaling : Adding more machines to a system to handle increased load
6. Vertical scaling : Adding more resources (CPU, RAM) to a single machine to handle increased load
7. Reconciliation : The process of ensuring that data from different sources is consistent and accurate
8. Dimension Vs Fact Table : Dimension tables contain descriptive attributes related to the dimensions of the data, while fact tables contain quantitative data and foreign keys referencing dimension tables
9. RDBMS : Relational Database Management System, a software system that manages relational databases
10. NoSQL : A type of database that provides a mechanism for storage and retrieval of data that is modeled in means other than the tabular relations used in relational databases
11. OLAP : Online Analytical Processing, a category of software tools that provides analysis of data stored in a database
12. OLTP : Online Transaction Processing, a class of systems that facilitate and manage transaction-oriented applications
13. Golden Gate : A term used to describe a critical point in a process or system where significant changes or decisions are made
14. Schema On Read : A data processing approach where the schema is applied to the data at the time of reading, allowing for flexibility in handling diverse data formats
15. Schema On Write : A data processing approach where the schema is applied to the data at the time of writing, ensuring that the data conforms to a predefined structure
16. SparkSession : The entry point for programming Spark with the Dataset and DataFrame API. It provides a unified interface for interacting with Spark's various components, including Spark SQL, DataFrames, and Datasets
17. SparkContext : The entry point for low-level Spark functionality. It represents the connection to a Spark cluster and allows users to create RDDs, accumulators, and broadcast variables
18. SparkSession Vs SparkContext : SparkSession is the entry point for high-level Spark APIs (DataFrames, Datasets, SQL), while SparkContext is the entry point for low-level Spark functionality (RDDs, accumulators, broadcast variables)
19. DataFrame : A distributed collection of data organized into named columns, similar to a table in a relational database
20. RDD : Resilient Distributed Dataset, a fundamental data structure in Spark that represents an immutable distributed collection of objects that can be processed in parallel
21. Spark Application : A self-contained program that runs on a Spark cluster and performs data processing tasks
22. Spark Architecture : Spark architecture consists of a cluster manager and worker nodes. The cluster manager is responsible for managing the resources and scheduling tasks, while the worker nodes execute the tasks
23. Driver : The driver is the process that runs the main() function of a Spark application and is responsible for creating the SparkContext, coordinating the execution of tasks, and collecting results
24. Executor : Executors are worker processes that run on the worker nodes in a Spark cluster. They are responsible for executing tasks and storing data in memory or on disk
25. Task : A task is the smallest unit of work that can be executed in Spark. Each task is assigned to an executor and performs a specific operation on the data.
26. Cluster Manager : A cluster manager is responsible for managing the resources of a Spark cluster and scheduling tasks. Examples of cluster managers include YARN, Mesos, and Kubernetes
27. HDFS : Hadoop Distributed File System, a distributed file system that provides high-throughput access to data across a cluster of machines
28. DBFS : Databricks File System, a distributed file system that is optimized for use with Apache Spark and provides high-performance access to data stored in the cloud
29. In-Memory Computing : A computing approach where data is stored in memory for faster access and processing, reducing the need for disk I/O operations
30. Caching : The process of storing frequently accessed data in memory for faster retrieval, reducing the need for repeated computations or disk I/O operations
31. RDD Transformation : RDD transformations are operations that create a new RDD from an existing one, such as map(), filter(), and reduceByKey(). Transformations are lazy and are not executed until an action is called
32. RDD Action : RDD actions are operations that trigger the execution of transformations and return a result to the driver program or write data to an external storage system, such as collect(), count(), and saveAsTextFile()
33. Action Vs Transformation : Transformations are operations that create a new RDD from an existing one and are lazy, while actions trigger the execution of transformations and return a result or write data to an external storage system
34. Lazy Evaluation : Lazy evaluation is a programming technique where the evaluation of an expression is delayed until its value is actually needed. In Spark, transformations are lazy and are not executed until an action is called
35. Broadcast Variables : Broadcast variables are read-only variables that are cached on each worker node, allowing for efficient sharing of large datasets across the cluster
36. ETL : Extract, Transform, Load, a data integration process that involves extracting data from source systems, transforming it into a desired format, and loading it into a target system for analysis or reporting
37. ELT : Extract, Load, Transform, a data integration process that involves extracting data from source systems, loading it into a target system, and then transforming it into a desired format for analysis or reporting
38. Data Lake : A centralized repository that stores large amounts of structured and unstructured data in its native format for later analysis and processing
39. Delta Lake : An open-source storage layer that brings ACID transactions to data lakes, enabling reliable and scalable data processing and analytics
40. Delta Live Tables : A feature of Delta Lake that allows for the creation of managed tables with ACID transaction support, enabling reliable and scalable data processing and analytics
41. Data Lakehouse : A data architecture that combines the benefits of data lakes and data warehouses, providing a unified platform for storing, processing, and analyzing structured and unstructured data
42. Data Warehouse : A centralized repository that stores structured data from multiple sources, optimized for querying and analysis
43. Data Mart : A subset of a data warehouse that is focused on a specific business area or department, providing targeted access to relevant data for analysis and reporting
44. Data Pipeline : A series of data processing steps that extract, transform, and load data from source systems to target systems for analysis or reporting
