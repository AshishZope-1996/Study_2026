## **Section 1: Introduction to PySpark Architecture**

**Q1. What is Apache Spark?**

Apache Spark is an open-source, distributed data processing engine designed to process large volumes of data across multiple machines.

Key features:

- Distributed processing.
- In-memory computation.
- Fault tolerance.
- Parallel execution.
- Batch and stream processing.
- Integration with multiple data sources.

**Q2. What is PySpark?**

PySpark is the Python API for Apache Spark. It allows developers to use Python to perform distributed data processing using Spark.

```
from pyspark.sql import SparkSessionspark = SparkSession.builder \    .appName("AshishApplication") \    .getOrCreate()
```

**Q3. Explain Apache Spark Architecture.**

Spark follows a master-worker-style distributed execution architecture.

Its major components are:

1. Driver Program
2. SparkSession
3. Cluster Manager
4. Worker Nodes
5. Executors
6. Tasks
7. Jobs
8. Stages

**Q4. What is a Driver Program?**

The Driver is the central process responsible for coordinating a Spark application.

Responsibilities:

- Creates SparkSession and SparkContext.
- Builds the execution plan.
- Coordinates job execution.
- Schedules tasks.
- Collects results from executors.

**Q5. What is SparkSession?**

SparkSession is the main entry point for working with Spark SQL and DataFrame APIs.

```
from pyspark.sql import SparkSessionspark = SparkSession.builder \    .appName("AshishApplication") \    .master("local[*]") \    .getOrCreate()
```

**Q6. What is SparkContext?**

SparkContext is the lower-level entry point that connects the Driver Program to the Spark execution environment.

```
sc = spark.sparkContext
```

**Q7. What is a Cluster Manager?**

A Cluster Manager manages resources across the cluster and allocates resources to Spark applications.

Common cluster managers:

- Standalone.
- YARN.
- Kubernetes.

**Q8. What is a Worker Node?**

A Worker Node is a machine in the cluster that provides resources for executing Spark applications.

**Q9. What is an Executor?**

An Executor is a process launched for a Spark application on a worker node.

Responsibilities:

- Executes tasks.
- Stores cached data.
- Reports task status.
- Returns results to the Driver.

**Q10. What is the difference between Driver and Executor?**

The Driver coordinates the application, whereas Executors execute distributed tasks and process data.

## **Section 2: Spark Execution Components**

**Q11. What is a Spark Application?**

A Spark Application is a program that runs on the Spark engine to process data.

It consists of:

- One Driver.
- One or more Executors.
- Jobs generated by actions.
- Tasks distributed across executors.

**Q12. What is a Spark Job?**

A Job is created when an action is executed on a DataFrame or RDD.

Examples of actions:

```
df.show()df.count()df.collect()df.write.csv("/output/data")
```

**Q13. What is a Stage in Spark?**

A Stage is a group of tasks that can execute without crossing a shuffle boundary.

Spark divides a job into multiple stages based on dependencies between operations.

**Q14. What is a Task in Spark?**

A Task is the smallest unit of execution in Spark. It processes one partition of data.

For example, if a stage has 10 partitions, Spark generally creates 10 tasks for that stage.

**Q15. Explain the difference between Job, Stage and Task.**

- Job: Created by an action.
- Stage: A group of tasks separated by shuffle boundaries.
- Task: Processes an individual partition.

**Q16. What is DAG in Apache Spark?**

DAG stands for Directed Acyclic Graph.

It represents the sequence of transformations required to execute a Spark job.

Spark uses DAG scheduling to optimize and organize execution.

**Q17. What is DAG Scheduler?**

DAG Scheduler converts a Spark job into stages based on dependencies.

Responsibilities:

- Analyzes the execution plan.
- Identifies shuffle boundaries.
- Creates stages.
- Submits stages for execution.

**Q18. What is Task Scheduler?**

Task Scheduler schedules individual tasks within stages and sends them to available executors.

**Q19. What is a Spark UI?**

Spark UI is a web-based monitoring interface used to understand and troubleshoot Spark applications.

It provides information about:

- Jobs.
- Stages.
- Tasks.
- Executors.
- Storage.
- SQL queries.
- Environment configurations.

Default URL in many local configurations:

```
http://localhost:4040
```

**Q20. Explain the complete execution flow of a Spark application.**

1. User submits a PySpark application.
2. Driver starts.
3. SparkSession is created.
4. Cluster Manager allocates resources.
5. Executors are launched.
6. User transformations build a logical plan.
7. An action triggers execution.
8. Spark optimizes the plan.
9. DAG Scheduler creates stages.
10. Task Scheduler distributes tasks.
11. Executors process partitions.
12. Results are returned or written to storage.

## **Section 3: Spark Data Processing Concepts**

**Q21. What is an RDD?**

RDD stands for Resilient Distributed Dataset.

It is an immutable, distributed collection of objects that can be processed in parallel.

```
rdd = spark.sparkContext.parallelize([10, 20, 30, 40])print(rdd.collect())
```

**Q22. What is a DataFrame in PySpark?**

A DataFrame is a distributed collection of data organized into named columns.

```
data = [    (1, "Ashish", 50000),    (2, "Rahul", 60000)]columns = ["id", "name", "salary"]df = spark.createDataFrame(data, columns)df.show()
```

**Q23. What is a Dataset in Apache Spark?**

Dataset is a strongly typed distributed collection available in Scala and Java Spark APIs.

PySpark primarily works with DataFrames rather than exposing the typed Dataset API.

**Q24. What is Lazy Evaluation in Spark?**

Lazy Evaluation means Spark does not execute transformations immediately.

It builds an execution plan and executes it when an action is called.

```
df_filtered = df.filter(df.salary > 50000)# Execution is triggered heredf_filtered.show()
```

**Q25. What are Transformations in Spark?**

Transformations create a new RDD or DataFrame from an existing one.

Examples:

```
df.select("name")df.filter(df.salary > 50000)df.withColumn("bonus", df.salary * 0.10)df.drop("salary")df.distinct()
```

**Q26. What are Actions in Spark?**

Actions trigger execution of the transformations.

Examples:

```
df.show()df.count()df.collect()df.first()df.take(5)
```

**Q27. What is the difference between Narrow and Wide Transformations?**

Narrow transformations do not require data to be shuffled across partitions.

Examples:

- filter()
- select()
- map()

Wide transformations require data movement across partitions.

Examples:

- groupBy()
- distinct()
- repartition()
- join() in typical shuffle-based execution.

**Q28. What is Shuffle in Spark?**

Shuffle is the process of redistributing data across partitions, usually across executors.

It commonly occurs during:

- GroupBy.
- Joins.
- Distinct.
- Repartition.

Shuffle can be expensive because of network transfer, disk I/O and serialization.

**Q29. What is Partitioning in Spark?**

Partitioning divides a large dataset into smaller logical chunks so that Spark can process them in parallel.

```
print(df.rdd.getNumPartitions())
```

**Q30. What is the difference between repartition() and coalesce()?**

`repartition()` performs a shuffle and can increase or decrease partitions.

`coalesce()` generally reduces partitions while avoiding a full shuffle by default.

```
df_repartitioned = df.repartition(10)df_coalesced = df.coalesce(2)
```

## **Section 4: Spark Optimization and Performance**

**Q31. What is Catalyst Optimizer?**

Catalyst is Spark SQL's query optimization framework.

It optimizes logical query plans before physical execution.

Its optimization techniques include:

- Predicate pushdown.
- Constant folding.
- Projection pruning.
- Boolean simplification.

**Q32. What is Tungsten Execution Engine?**

Tungsten is a set of Spark execution improvements designed to improve CPU and memory efficiency.

It introduced techniques such as:

- Efficient memory management.
- Binary processing.
- Whole-stage code generation.

**Q33. What is Predicate Pushdown?**

Predicate Pushdown moves filter conditions closer to the data source to reduce the amount of data read.

```
df = spark.read.parquet("/data/employees")filtered_df = df.filter("salary > 50000")
```

**Q34. What is Projection Pushdown?**

Projection Pushdown reads only the required columns instead of loading all columns.

```
df = spark.read.parquet("/data/employees")result = df.select("name", "salary")
```

**Q35. What is Broadcast Join?**

Broadcast Join sends a small DataFrame to executors so it can be joined with a larger DataFrame without shuffling the large side for that join.

```
from pyspark.sql.functions import broadcastresult = large_df.join(    broadcast(small_df),    "department_id",    "inner")
```

**Q36. What is Adaptive Query Execution (AQE)?**

AQE dynamically optimizes the physical execution plan using runtime statistics.

Important capabilities:

- Coalescing shuffle partitions.
- Converting sort-merge joins to broadcast joins when appropriate.
- Optimizing skewed joins.

```
spark.conf.set(    "spark.sql.adaptive.enabled",    "true")
```

**Q37. What is Data Skew?**

Data Skew occurs when some partitions contain significantly more data than others.

It can cause certain tasks to take much longer than the rest.

Solutions:

- Salting.
- Broadcast joins where appropriate.
- AQE skew join optimization.
- Better partitioning strategies.

**Q38. What is Caching in PySpark?**

Caching stores a DataFrame's computed data for reuse.

```
df.cache()df.count()
```

**Q39. What is Persist in PySpark?**

Persist stores a DataFrame or RDD using a specified storage level.

```
from pyspark import StorageLeveldf.persist(StorageLevel.MEMORY_AND_DISK)
```

**Q40. How can you identify the execution plan of a DataFrame?**

Use `explain()` to understand the logical and physical execution plans.

```
df.explain(True)
```

## **Section 5: Advanced PySpark Architecture**

**Q41. What is Serialization in Spark?**

Serialization converts objects into a format suitable for storage or transmission across the network.

It is important for data transfer, caching and distributed execution.

**Q42. What is the difference between Client Mode and Cluster Mode?**

In Client Mode, the Driver runs on the machine that submits the application.

In Cluster Mode, the Driver runs inside the cluster.

**Q43. What is Dynamic Resource Allocation?**

Dynamic Resource Allocation allows Spark to increase or decrease the number of executors depending on workload requirements.

```
spark.conf.set(    "spark.dynamicAllocation.enabled",    "true")
```

This setting requires a compatible cluster setup and shuffle preservation configuration.

**Q44. What is Speculative Execution?**

Speculative Execution launches duplicate attempts of slow-running tasks on other executors.

It helps reduce the impact of unusually slow tasks.

```
spark.conf.set(    "spark.speculation",    "true")
```

**Q45. What is Fault Tolerance in Spark?**

Fault Tolerance is Spark's ability to recover from failures during distributed processing.

Spark uses:

- RDD lineage.
- Task retries.
- Stage retries.
- Executor recovery mechanisms.
- Checkpointing where configured.

**Q46. What is Checkpointing in Spark?**

Checkpointing saves data to reliable storage to truncate long lineage and support recovery.

```
spark.sparkContext.setCheckpointDir(    "/checkpoint/spark")df.checkpoint()
```

**Q47. How does PySpark communicate with the JVM?**

PySpark uses Py4J to communicate between Python and the JVM-based Spark engine for many DataFrame and Spark API operations.

Python UDFs can also involve Python worker processes to execute Python code.

**Q48. What is Structured Streaming?**

Structured Streaming is Spark's scalable stream-processing engine built on the Spark SQL engine.

It processes streaming data using DataFrame and Dataset-style operations.

```
stream_df = spark.readStream \    .format("socket") \    .option("host", "localhost") \    .option("port", 9999) \    .load()
```

**Q49. What is the role of Executors in memory management?**

Executors use memory for several purposes:

- Execution memory for operations such as joins and aggregations.
- Storage memory for cached and persisted data.
- Other JVM and application overhead.

Memory configuration and execution behavior affect application performance.

**Q50. How do you troubleshoot a slow PySpark application?**

A systematic troubleshooting approach includes:

1. Check Spark UI.
2. Identify slow stages.
3. Inspect task execution time.
4. Check data skew.
5. Review shuffle read and write.
6. Verify partition counts.
7. Inspect the physical execution plan.
8. Check memory and GC activity.
9. Evaluate broadcast join opportunities.
10. Review AQE and Spark configurations.

## **Section 6: Practical Architecture-Based Interview Scenarios**

These questions test whether you understand how Spark works internally rather than just remembering definitions.

**Q51. What happens internally when you execute&#x20;**`df.show()`**?**

1. Spark receives the action.
2. The query plan is prepared and optimized.
3. The execution plan is generated.
4. Required stages and tasks are created.
5. Executors process the required partitions.
6. A limited number of rows are returned to the Driver for display.

**Q52. What happens when an Executor fails?**

- The Driver detects the executor failure.
- Tasks running on the failed executor may be rescheduled.
- Lost cached data may need to be recomputed.
- Spark retries failed tasks and stages according to its configuration.

**Q53. Why is&#x20;**`collect()`**&#x20;dangerous when working with large datasets?**

`collect()` transfers all rows from executors to the Driver.

This can cause Driver memory exhaustion and application failure.

```
# Avoid on large datasetsdf.collect()# Better for inspecting a small sampledf.show(10)
```

**Q54. What is the difference between Cache and Checkpoint?**

Cache keeps computed data available for reuse, whereas checkpoint saves data to reliable storage and truncates lineage.

**Q55. How does Spark achieve parallel processing?**

Spark divides data into partitions and schedules tasks to execute those partitions concurrently across available executors.

**Q56. What is the difference between&#x20;**`spark-submit`**&#x20;and SparkSession?**

`spark-submit` is a command-line utility used to submit Spark applications.

SparkSession is the programming interface used inside a Spark application to interact with Spark.

**Q57. What is the role of PySpark Python Workers?**

Python workers execute Python functions such as Python UDFs. They communicate with the JVM-based Spark execution environment.

**Q58. What is Whole-Stage Code Generation?**

It is a Spark SQL optimization that combines multiple physical operators into generated code to improve execution efficiency.

**Q59. What is the difference between Spark SQL and PySpark DataFrame API?**

Spark SQL allows users to query structured data using SQL syntax, while the PySpark DataFrame API allows users to perform similar operations using Python methods.

Both use Spark SQL's underlying execution engine.

**Q60. What are the most important factors affecting Spark application performance?**

- Number of partitions.
- Data volume.
- Data skew.
- Shuffle operations.
- Join strategies.
- Memory allocation.
- Serialization.
- File formats.
- Query optimization.
- Cluster resources.
